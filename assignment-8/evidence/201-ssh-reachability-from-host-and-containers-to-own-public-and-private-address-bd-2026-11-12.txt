=== Why (the explanation is an inference from the results and the security group rules; it was not tested separately) ===
The AWS security group admits SSH (22) only from single administrator addresses (home and campus, Assignment 7); a connection made from the server itself to its own public address
arrives with the Elastic IP as its source, which is not in that list, so it is refused. A connection to the private address stays inside the instance and is not filtered by the security group.
Port 443 does not have this problem (it is open to everyone, which is why the Blackbox Exporter container can probe the public HTTPS names, evidence 112 of Assignment 7).

=== Consequence ===
The deployment's SSH connection must use the private address (172.31.29.240) or the Docker gateway, not git.ssw590-g1.tech; the HTTPS health checks in the playbook may keep using the public names.
No security group rule is added for this (the alternative would be to open 22 to the Elastic IP itself, which is a firewall change and not needed).
