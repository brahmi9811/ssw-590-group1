=== Result: build #5 FAILED after 26 s, in the stage "Dependency and secret scans" ===
Archived artifacts: release.example.yml, pip-audit.exit, tool-versions.txt. pip-audit.exit contained "pip-audit exit 1"; there was NO pip-audit.json. The pipeline treats a missing report as a failed scan (set -e, test -s), so nothing after it ran: no image, no push, no deploy.

=== Cause (found by re-running the same command inside the agent) ===
PermissionError: [Errno 13] Permission denied: '/home/jenkins/.cache/pip-audit'
The Trivy cache volume is mounted at /home/jenkins/.cache/trivy; Docker created the parent /home/jenkins/.cache as root, so the jenkins user could not create pip-audit's cache directory.

=== Fix (Nov 17, 03:49 UTC) ===
Dockerfile of the agent: mkdir -p /home/jenkins/.cache/trivy and chown -R jenkins:jenkins /home/jenkins/.cache before USER jenkins.
compose.yaml: new volume trivy_db (so its owner comes from the image), image tag group1/jenkins-delivery-agent:2.
Build: DOCKER_BUILDKIT=0 docker build -t group1/jenkins-delivery-agent:2 .  (Successfully built ec2946912ce9); docker compose up -d recreated the container; log: "WebSocket connection open", "Connected".
After: /home/jenkins/.cache and /home/jenkins/.cache/trivy are owned by jenkins; mkdir /home/jenkins/.cache/pip-audit works. The workspace volume agent_work was kept.
